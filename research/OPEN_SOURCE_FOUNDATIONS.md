# Open-source foundations for the consolidated talent platform

Observed October 11, 2026 in Los Angeles; GitHub timestamps are UTC. This is a **static source audit**, not a runtime certification. Upstream code was downloaded as text for inspection; no upstream packages, containers, models, migrations, or scripts were executed. The exact API responses, source hashes, retrieval failures, and repository pins are preserved in [OPEN_SOURCE_EVIDENCE.json](./OPEN_SOURCE_EVIDENCE.json). The complete recursive tree responses are retained in the compressed evidence archive referenced there.

## Recommendation

Keep the new project's own candidate, evidence, consent/exclusion, requisition, and pipeline contracts authoritative. Evolve the working email finder and reusable existing talent/VitalCV modules through adapters. Use PRISM as a reference for the broader candidate/recruiter workflow, but **do not make its published repository the executable backbone**: the inspected commit is missing an imported model module, writes fabricated assessment results in a worker, and exposes important routes without authentication dependencies.

For a complete ATS benchmark, compare **Odoo Recruitment** and **Frappe HRMS** first. For a modern recruiting CRM extension, investigate **Twenty's application APIs and MIT SDK**, keeping its AGPL core and commercial files outside a proprietary source copy. **Horilla** and **OpenCATS** provide useful pipeline and security-regression examples. **pgvector** is a credible optional search component once an existing Postgres owner and a measured retrieval need justify it. **OpenResume** is a narrow parsing reference with stale maintenance; **Cal.diy** is a scheduling reference with a current upstream production caveat. None supplies a lawful global candidate database or evidence that our eventual platform outperforms competitors.

## Concrete foundation choice

1. **Immediate:** maintain our small working public-source discovery as one module. Add requisitions, reviewed candidate dossiers, explicit evidence, and pipeline records through owned contracts. Keep unknown deliverability and a persistent exclusion registry. A public company contact address must not become an asserted personal candidate email.
2. **ATS comparison:** map a single requisition → evidence-supported candidate → human-approved shortlist → interview feedback workflow against Odoo and Frappe. Reuse field/state concepts; only import code after choosing a license architecture. Measure manual work and correction rates in the same real workflow.
3. **CRM option:** spike a Twenty custom application/API adapter if a shared recruiting relationship system saves more work than extending the existing store. Retain person/contact provenance and avoid automatic identity merges.
4. **Search option:** begin with keyword/filter retrieval and transparent evidence. Evaluate pgvector against that baseline after enough authorized profiles exist. Store embedding version and link every result to its original claims; no inferred fit should be presented as a verified credential.
5. **Later modules:** add scheduling against a known calendar owner and interview capture with participant authorization. Cal.diy and OpenResume are reference candidates, not proof those later workflows are ready.

Acceptance for any borrowed component is a successful local workflow with realistic data and denial tests, not installation, stars, a root README, or a passing unrelated upstream action. The cheapest useful competitive test is a recruiter completing the same small task with this platform and their existing tools, recording source correctness, appropriate shortlist quality, time, and manual corrections. Current research establishes neither global competitor superiority nor production qualification.

- Source-file retrieval failures are retained in JSON, including guessed test paths and the absent old Cal.com enterprise license path. Correct pgvector recall paths were subsequently fetched. No failed fetch is treated as source evidence.
- No upstream runtime, dependency audit, local test execution, load test, deployment, candidate evaluation, or license-compliance assessment was performed. No private LinkedIn data, paid contact database, model call, automated employment decision, or outbound message was used.
